Why · 问题

开放性知识工作的真实困境

信息散落

工具太多，线索太碎

选题、文献、笔记、日程、生活记录分散在 5+ 个 App，研究者在不同入口间反复切换，缺少统一工作台。

收藏 ≠ 理解

「存了」不等于「读了」

顶刊论文收藏即结束；摘要是英文、方法陌生，阅读门槛高，大量资料沉睡在收藏夹里。

跨端割裂

电脑写、手机记，对不上

实验室用电脑、通勤用手机，数据不互通；想「随手记一条灵感」却要回到电脑端才能落地。

被动接收

信息过载，缺乏过滤

推送 overwhelms；缺少「与我方向相关」的筛选，研究者的注意力被稀释。

→ 研习台的目标：把「信息流」变成「可行动的科研线索」，让 AI 替你做过滤、翻译与结构化。

What · 定位

研习台 = 科研与生活的统一工作台

一个打开网页即用的工具：数据自主、AI 辅助、跨端无缝。无后端、无账号、零成本部署。

🗂 科研主线

顶刊每日推荐、论文追踪（选题→投稿→录用）、项目、方向、研读笔记、成果档案。

🌱 生活侧写

运动、阅读观影、旅行、习惯打卡，以及周/月/年阶段回顾，呼应「学者也是完整的人」。

⚡ 低摩擦捕获

悬浮按钮 + 底部速记面板，灵感/选题/文献/待办一键入箱，记完即走。

移动端 随手记↔ 云端 单一真相源↔ 电脑端 深阅读/管理
同一套网页，同一份数据，手机与电脑共享。
Design · 理念

四条贯穿始终的设计原则

  • 本地优先 · 数据自主——研究者的私密数据默认存本地，可选自建云端；不依赖任何商业平台，随时可导出。
  • AI 做「过滤器 / 翻译器 / 结构器」——不是堆砌大模型，而是用轻量 API 把信息筛成与你相关的、能读懂的、成体系的科研线索。
  • 低摩擦捕获——灵感稍纵即逝，记录动作要 ≤ 2 次点击；先记下来，再整理。
  • 科研与生活一体化——把生活记录与阶段回顾纳入工作台，让「复盘」成为习惯而非负担。
Highlight 01 · AI 核心

顶刊每日推荐 + 自动相关性打分

不是「推论文」，而是按你的研究方向，把海量顶刊变成一份「与你相关的待读清单」。

流水线：OpenAlex → 顶刊过滤 → 相关性打分 → 待读清单
  • 数据源 OpenAlex：免费、免密钥、浏览器可直连，覆盖 UTD24/FT50 等 60+ 顶刊近 45 天新文。
  • 内置方向词典（数字化转型 / AI / 创新 / 专利 / 平台经济…）与方法词典（DID / IV / 文本分析 / 实验…）自动打分。
  • 输出不只给标题，还给出「为什么值得你读」的方向关联说明，引导做中国情境或选题迁移。
  • 结果当日缓存到本地，每天只请求一次，省流量也更快。
Highlight 02 · 降门槛

一键摘要翻译：把顶刊读「懂」

主通道

微软 Edge 翻译接口

免密钥、CORS 开放、国内可直连。Token 8 分钟缓存，按论文 id 缓存译文，同一篇只翻一次。

备用通道

Google gtx 兜底

主通道异常时自动切换，保证「读得了」。带超时控制，单篇不卡死整体。

价值：把英文摘要、方法说明翻译成中文对照，显著降低顶刊阅读门槛——尤其对快速判断「这篇与我何干」极为高效。

设计取舍：用免费公开接口而非自建模型服务，符合「零成本、可直连、易维护」的个人工具定位。

Highlight 03 · 管理

科研全生命周期，一处管完

📄 论文追踪

选题构思→文献综述→方法设计→初稿→投稿→返修→录用→发表，阶段流一目了然。

📁 项目 / 方向

学术研究、学科竞赛、实习实践分类型管理；研究方向独立成册，论文可挂接方向。

📝 笔记 / 成果

研读笔记随手写；成果档案（论文/项目/获奖/会议）自动统计，一键导出清单。

把「想到—读—做—成」的闭环沉淀在同一处，减少在不同工具间搬运的损耗。

Highlight 04 · 复盘

生活侧写 + 阶段回顾

🌿 生活记录

运动（次数/时长/连续天数）、阅读与观影、旅行计划、习惯打卡——科研之外，生活也被温柔记录。

📊 周 / 月 / 年回顾

自动生成阶段小结与完成率条形图，把科研进展、生活记录、阅读思考、习惯坚持汇成一份「给自己的复盘」。

设计主张：研究者首先是完整的人。回顾功能让长期主义可见、可坚持。

Highlight 05 · 捕获

灵感收集箱 + 快速记录

  • 右下角悬浮按钮（FAB）随时唤起速记面板，灵感/选题/文献/生活/待办一键分类入箱。
  • 支持「存为今日任务」，捕获即行动，灵感不流失到别处。
  • 首页置顶「随手记一条灵感 / 选题…」，低摩擦、零心智负担，契合知识工作的即兴性。

这是「低摩擦捕获」原则最直接的产品落点：先收集、后整理，避免好点子沉没。

Technical · 总览

技术路线：一个纯前端的轻量架构

无后端、无数据库：前端直接消费开放 API，数据本地优先 + 可选云端。

一句话：前端即应用，开放 API 即服务，浏览器即数据库。零服务器成本，个人即可长期维护。

Core · 重点

移动端与电脑端，如何同步？

三层方案，层层兜底，保证「一处更新、处处同步」且手机/电脑体验一致。

第一层 · 同源

同一套代码

同一份静态托管（GitHub Pages），手机电脑打开同一 URL 即同一应用。断点 780px 切换导航形态：桌面侧栏 ↔ 移动底部 Tab，数据与逻辑完全共用。

第二层 · 同步

本地优先 + 云端真相源

整份应用状态 = 一个 JSON。localStorage 本地优先；开启同步后存 JSONBin 云端，启动拉取、本地更旧则采用云端（last-write-wins + 时间戳），保存防抖后推送。

第三层 · 更新

版本自更新

每次发布更新 version.txt；手机端打开时 checkUpdate 发现新版本自动重载，无需应用商店即可拿到新功能。

降级策略：未配置云端 / 断网时，自动回退为纯本地（localStorage），功能不中断——这是「优雅降级」原则的体现。

Core · 机制

同步时序：手机 ↔ 云端 ↔ 电脑

last-write-wins（以 savedAt 时间戳为准）；推送前 700ms 防抖 + 单飞（in-flight），避免并发覆盖。 适用场景：单人多端、非并发编辑——个人知识工作的典型形态。
同步示意：双端各持本地副本，以云端为仲裁，时间戳决定胜负。
Core · 零成本

零成本开放 API 架构

📚 OpenAlex（论文）

完全免费、无需密钥、支持浏览器跨域直连。按期刊 ISSN + 时间窗过滤，返回结构化 JSON，前端直接计算相关性。

🌐 Edge / Google（翻译）

微软 Edge 翻译接口国内可直连、免密钥；Google gtx 作兜底。两通道皆带超时，保障可用。

可复用的缓存策略

  • 论文推荐：按「当天」缓存到 localStorage，每日只请求一次。
  • 摘要译文：按论文 id 缓存，同一篇只翻译一次；缓存上限 240 条，超量按时间淘汰。
  • 统一收益：省流量、提速、降低对第三方接口的依赖与受限风险。
Core · 工程

值得复用的工程实践

  • 单一数据源 + 规范化（normalize）：整份应用状态是一个 JSON 对象；读入即归一（补默认字段、修类型），渲染层永远拿到「干净」的结构。
  • 版本迁移（v1 → v2）：旧数据自动拆分项目/论文、ICS 任务转日历事件，老用户升级无感。
  • 渐进增强 / 优雅降级：同步失败不阻塞、翻译失败回退、本地存储满则放弃缓存——任何一环出问题，核心功能仍可工作。
  • 零框架、零构建：纯 HTML/CSS/JS，单文件即可运行；也可打包进 dist/。维护成本低，适合个人长期持有。
Other · 反思

方法论：AI 在知识工作中的三角色

🔻 过滤器

从信息洪流中筛出「与我相关」，对抗注意力稀释。

🔤 翻译器

把语言/方法门槛拉平，让顶刊真正可读可用。

🧱 结构器

把零散灵感组织成可追踪的科研进程与复盘。

元实践视角：这个工具本身的构建，也是「用 AI 辅助完成 AI 工具」的开放知识工作范例——需求、设计、编码、部署一体打通。

Other · 展望

局限与下一步

当前局限

同步是「近似一致」

last-write-wins 适合单人多端非并发；若两端同时改，后写覆盖先写，无自动合并。

下一步

真正的多端实时协同

引入 Yjs / CRDT 做字段级合并，支持离线编辑后无冲突合并；可拓展到多人课题组共用。

当前局限

翻译依赖第三方免费接口

受配额与可用性影响，需关注稳定性。

下一步

能力延展

RSS 订阅、BibTeX 导出、Notion 同步、AI 摘要总结；并把推荐词典做成可自定义。
